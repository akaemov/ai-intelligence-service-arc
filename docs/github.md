# GitHub и публикация

Репозиторий публичный. GitHub Pages настроен владельцем на `gh-pages`, корень. [Сайт](https://akaemov.github.io/ai-intelligence-service-arc/).

В Actions выберите «Исследование спроса» → Run workflow. `parameters` — JSON допустимых параметров, например:

```json
{"mode":"selected_regions","regions":["Республика Башкортостан"],"days":90,"groups":["requests","procurement","vacancies","media"]}
```

По умолчанию `publish=false`: результаты сохраняются как обезличенный артефакт. `publish=true` публикует проверенный сайт в настроенную ветку `gh-pages`, включая частичный отчёт с видимыми ограничениями. Это не означает принятие исследования как полного. Фатальная ошибка или отклонение проверки контактов/секретов останавливает публикацию. При полном отказе источников сохраняется предыдущий доступный отчёт и отдельная новая попытка.

Workflow «Реальный сбор России» позволяет отдельно проверить сбор и сохранить безопасные JSON в `research-data`. Workflow «Проверка публичного сайта» проверяет HTTPS-страницу, JS/CSS и фактический JSON v2. CI выполняет Python-тесты и сборку интерфейса. Публикация использует `GITHUB_TOKEN` с `contents:write`, без отдельного пользовательского токена. Внутреннее состояние и контакты не входят в артефакты.

Для ручной публикации уже проверенного результата:

```bash
npm --prefix web run build -- --base=/ai-intelligence-service-arc/
touch web/dist/.nojekyll
python scripts/publish_branch.py web/dist gh-pages
```

Повторная публикация требует ранее данного разрешения владельца или явного выбора `publish=true`. Нельзя публиковать `.state/`, `.env`, SQLite или raw-кэш. Новые источники/LLM подключаются после проверки правил доступа и тарифа, секреты вводятся через защищённые настройки.
